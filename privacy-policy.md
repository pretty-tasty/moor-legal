# Moor — Privacy Policy

_Last updated: 2026-04-29_

Moor is an ADHD task-companion app that reads connected Google accounts to
surface the most useful task to do today. This policy describes what Moor
reads, what it stores, who it shares with, and your rights over the data.

## Who runs Moor

Moor is a personal project run by Christopher Banham, contactable at
**drink@fountainheadwinehouse.com**. As of April 2026 it is used only by the
author. Phase 4 of the roadmap may extend access to a small number of people
via Apple TestFlight; this policy will be updated if that changes who has
access to your data.

## What Moor reads from your Google account

When you connect a Google account, Moor requests two read-only scopes:

- **`https://www.googleapis.com/auth/gmail.readonly`** — to scan recent email
  for task signals (bills, requests, deadlines) and completion signals (payment
  confirmations, replies). Moor reads message metadata only — sender, subject,
  snippet, date, and message ID. **It never sends, modifies, or deletes mail,
  and it does not read full message bodies beyond the snippet that Gmail
  returns in its metadata response.**
- **`https://www.googleapis.com/auth/calendar.readonly`** — to read upcoming
  events (title, start, end, attendees) so the daily brief can include
  external commitments and identify tasks that need preparation work started
  now. **No event data is modified.**

Moor also requests `openid` and `email` so it can show which account is
connected. No other scopes are requested.

## What Moor stores

All data is stored in Google Cloud Firestore in the project `moor-app-au`,
region `australia-southeast1`. Specifically:

- **OAuth refresh tokens** — encrypted at rest in Google Secret Manager.
  Required to access the connected Google accounts on a recurring schedule.
- **Pool items** (`pool/`) — derived task entries: text, deadlines, source
  references back to the original email or calendar event, status flags.
- **Daily briefs** (`briefs/`) — the morning brief produced for each day,
  including ranked tasks and the next 7 days of calendar commitments.
- **Reconciliation results** (`reconciliation_results/`) — periodic summaries
  of which items were auto-closed by completion-signal matching.
- **Pool snapshots** in Cloud Storage (`gs://moor-app-au-archive/archive/`) —
  daily JSON snapshots of the task pool for disaster recovery.

**Email and calendar data is not stored verbatim.** Moor stores only derived
representations. Each pool item carries a `source_ref` like
`gmail:account:msg_id` so the original message can be re-read from Gmail on
demand, but Moor's database does not hold the email body, calendar event
descriptions, or any other content beyond what is listed above.

## Third parties

Moor uses two third-party services:

- **Anthropic Claude API** — the daily brief is generated by Claude (model
  `claude-sonnet-4-6`). The prompt sent to Claude contains the email subject +
  snippet + sender, the calendar event metadata above, and the current pool of
  tasks. Anthropic's API terms commit to not training their models on customer
  API inputs.
- **Google Cloud Platform** — Firestore, Cloud Storage, Cloud Run, Secret
  Manager, Cloud Scheduler, Cloud Logging. All data resides in the
  `australia-southeast1` region.

No data is shared with any other party.

## How long data is kept

| Data | Retention |
| --- | --- |
| Pool items | Until you mark them done, or 90 days for `someday`-bucket items |
| Briefs | Indefinite (acts as a personal history) |
| Reconciliation results | 90 days, then automatically purged via Firestore TTL |
| Pool snapshots in Cloud Storage | 90 days, then automatically purged via lifecycle policy |
| OAuth refresh tokens | Until you revoke access (see below) |

## Your rights

You can:

- **Revoke Moor's access** at any time via your Google Account at
  <https://myaccount.google.com/permissions>. Revocation invalidates the
  refresh token; Moor stops reading your account on the next scheduled run.
- **Request deletion of all derived data** stored in Firestore by emailing
  drink@fountainheadwinehouse.com. The author will delete the relevant
  documents within 30 days and reply to confirm.
- **Inspect what Moor has stored about you** by emailing the same address; the
  author will provide a JSON export of every document tied to your connected
  account.
